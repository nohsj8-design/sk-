# 771 안내봇 · 문의 운영

## 답변 수정 위치
- `assets/chatbot/flow.json`: 질문 키워드, 고정 답변, 버튼과 다음 단계입니다. 긴 키워드가 우선입니다. 등록되지 않은 질문은 고정 안내로 돌아갑니다.
- `js/chatbot-rules.mjs`: 키워드 탐색과 저장 상태 검증입니다. AI API를 호출하지 않습니다.
- `assets/chatbot/inquiry-config.json`: 문의 서버 주소와 공개용 키입니다. 관리자 키를 넣으면 안 됩니다.
- `contact.html`과 챗봇은 `js/inquiry.js`를 공유하며 같은 Supabase `public.inquiries`에 접수합니다.

## 실제 운영 전에 정리할 답변
1. **오늘 조회수**: 한국시간 날짜별/채널별 데이터, 당일 완료 여부, 기준 시각이 필요합니다. 현재 `daily`가 비어 있어 숫자는 안내하지 않습니다.
2. **이번 주 인사이트**: 월요일부터 기준일까지의 완전한 일별 데이터, 비교 기간, 채널별 우수 콘텐츠 선정 기준이 필요합니다. 현재는 임시 안내입니다.
3. **FAQ**: 지표 정의·부분수집·누적과 기간 실적 차이는 등록했습니다. 운영자의 최종 수집 주기와 오류 처리 기준은 확정해야 합니다.
4. **제작 문의**: 실제 제공 서비스, 예상 답변 시간, 일정·견적 기준은 운영자가 확정해야 합니다. 자동 견적/일정 확약은 없습니다.

JSON을 바꾸면 다음 페이지 로딩부터 새 답변을 사용합니다. 진행 중인 대화는 현재 탭의 sessionStorage에만 유지됩니다. 초기화하면 저장 상태가 삭제됩니다. 문의 양식 초안은 저장하지 않습니다. 자유 입력 질문에도 개인정보를 넣지 않도록 안내합니다.

## 문의 보안
- Supabase Free 프로젝트 `art-chronicles-busan`의 기존 `inquiries`를 사용합니다. `source`는 `portfolio-contact-*` 또는 `portfolio-chatbot-*`입니다.
- 브라우저에는 공개용 키만 있습니다. 서버 전용 키는 Supabase Edge Function 환경에만 있습니다.
- 테이블의 RLS를 유지하고 anon/authenticated의 직접 접근을 철회합니다. 접수 RPC는 service_role만 실행합니다.
- 서버가 입력 길이·이메일·동의·허용 출처·허니팟·입력 소요 시간을 검증합니다. 출처 제한만을 인증 수단으로 간주하지 않습니다.
- DB에서 원자적으로 IP 해시당 시간당 3건, 이메일 해시당 하루 3건, 전체 하루 50건을 제한합니다. 원본 IP는 저장하지 않습니다.
- UUID 요청 ID로 같은 접수의 중복 저장을 막습니다. 오류 시 성공으로 표시하지 않습니다.
- 문의 개인정보는 접수 30일 이후 일일 정리 작업으로 삭제합니다. 다른 서비스 문의는 정리 대상에서 제외합니다.
- 관리자 확인은 Supabase Dashboard → Table Editor → inquiries입니다. 공개 관리자 목록 페이지는 제공하지 않습니다.

## 비용과 제한
생성형 AI, 외부 유료 메일 전송, 유료 요금제/애드온은 사용하지 않습니다. Free 범위에서 실행되며 한도 초과나 프로젝트 일시정지 시 문의가 중단될 수 있습니다. 무료 서비스의 무중단이나 절대적 보안은 보장하지 않습니다. Free 유지 상태를 Supabase에서 확인할 수 있습니다.

## 서버 원본과 검증
`supabase/portfolio-inquiry.sql`과 `supabase/functions/portfolio-inquiry/index.ts`가 서버 원본입니다. 공개 키를 쓰는 접수 함수는 gateway JWT 검증을 끄고 서버 코드에서 검증합니다. 향후 수정 시 Dashboard에 배포한 코드도 함께 갱신해야 합니다.

`node --test tests/chatbot.test.mjs`로 키워드 우선순위·분기·저장 상태 검증을 실행합니다. 실제 접수 테스트에는 명확한 테스트용 이름·이메일만 사용하고 테스트 UUID만 삭제합니다.
